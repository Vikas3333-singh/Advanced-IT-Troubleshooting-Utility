Case study

A 45-minute ticket, often a one-minute fix.

I wrote a Windows Batch script that lets employees fix eight common problems themselves: network and DNS faults, Windows Update, Teams and Outlook caches, the print spooler, system files, temp files, and a diagnostic report. It is one file that runs locally.

Time to resolution, typical case

30–45 minLog ticket, queue, remote session, technician runs commands
About 1 minOpen utility, pick a fix, repair runs locally

Estimates from the project brief, not instrumented measurements. The one-minute figure applies to quick fixes such as DNS, spooler and cache cleanup. SFC and Windows Update repair take longer.

Why the tickets took so long

  • Travelers outside support hours

    Consultants on hotel and airport Wi-Fi hit stale DNS and captive-portal drops while the service desk was closed, sometimes just before a client meeting.

  • Repeat tickets

    Corrupted update caches, hung print spoolers, network stack hangs and Teams or Outlook cache problems kept coming back, and each had the same fix.

  • Waiting took longer than fixing

    A DNS flush takes seconds, but logging the ticket, waiting for a technician and setting up a remote session pushed the total to 30 to 45 minutes.

  • Users couldn’t run the commands safely

    Commands like netsh int ip reset or clearing SoftwareDistribution need elevation, and a mistake can leave a laptop worse off than the ticket did.

Eight fixes in one file.

A menu-driven utility for employees and L1 technicians. Select a fix to see what it runs.

  1. LaunchLocal batch file, nothing to install
  2. ChooseGuided menu selection
  3. ConfirmAdmin check, then a confirmation prompt
  4. ResultThe repair runs, or a report is saved

How I built it.

  • It started with the ticket history

    Traveling consultants kept raising the same connectivity and update tickets. I built the tool on my own initiative so they could clear those themselves.

  • A numbered menu

    Users pick a number. Nobody has to type a command.

  • Checks before it changes anything

    It checks for administrator rights and asks for confirmation before running a repair. The cleanups restart services and clear caches. They don’t touch user files.

  • Nothing to install

    It’s plain Windows Batch, under 100 KB, and the repairs run locally without an internet connection.

What it changes

Travelers fix their own laptops

A consultant at a client site or abroad can clear a connectivity drop or an update hang without waiting for the service desk.

It targets the repeat L1 tickets

The focus is high-volume DNS, network and update tickets. I haven’t measured how many tickets it actually deflected.

Analysts can use it too

Service desk staff can run the same script in a remote session, so everyone applies the same fix. It costs nothing to license.
